# J.128 Krios `block` runtime capture history

- **attempt01 registered runtime — rejected.** The report claimed the registered Krios atlas at every frame, but independent review found that the two left-facing frame0 screenshots showed fallback artwork. The harness had warmed synchronous simulation ticks before the async image load completed; selector diagnostics were not proof of the rendered canvas. Preserve the original rejection at `attempt-01/registered-runtime/INDEPENDENT_REGISTERED_RUNTIME_REVIEW.md`.
- **attempt02 registered runtime — superseded.** A corrected source decode rendered the atlas, but the test still relied on the separate preloaded selector image and was not used as final normal-loader acceptance evidence.
- **attempt03 registered runtime — incomplete.** Diagnostic attempt was stopped after four screenshots; the partial output remains preserved and is not acceptance evidence.
- **attempt04 candidate and registered runtime — candidate passed; registered view superseded.** Candidate-injected art passed its independent 16-capture review. Registered captures also rendered the source after decode/preload, and their independent review passed; this is retained as useful intermediate evidence. The final review instead uses the normal app loader in attempt07.
- **attempt05 registered runtime — incomplete.** The image waited on Playwright's default animation-frame polling, while the capture harness disables `requestAnimationFrame` for deterministic manual ticks. The atlas did load through the app, but wait polling did not observe it; only right-facing partial screenshots were produced.
- **attempt06 registered runtime — incomplete.** The same polling bug remained after adding diagnostics; right-facing partial screenshots are preserved.
- **attempt07 registered runtime — accepted.** The harness now polls at a fixed 100ms interval and waits for the exact app `productionSpriteImages` entry populated by `beginMatch` / `loadProductionSprites`. It does not decode or insert an atlas itself. Independent review confirms all four registered frames in both facings and both zooms, with correct timing and no ball state or browser errors.
